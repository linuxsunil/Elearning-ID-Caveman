# Contributing

Contributions should make E-learning ID Caveman more useful without making it unnecessarily larger.

## Good contributions

- realistic e-learning examples;
- clearer instructional-design rules;
- Storyline, Rise, LMS and accessibility patterns;
- corrections to inaccurate or ambiguous guidance;
- tests showing that brevity preserves learning integrity.

## Before opening a pull request

1. State the instructional problem.
2. Keep the change concise.
3. Add or update an example when behaviour changes.
4. Confirm objectives, practice, assessment and feedback remain aligned.
5. Preserve exact technical identifiers in code or authoring-tool examples.
6. Do not include confidential learner, client or SME information.

## Pull request format

- **Problem**
- **Change**
- **Example**
- **Learning-integrity check**
